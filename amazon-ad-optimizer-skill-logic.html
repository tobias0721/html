亚马逊广告优化 Skill 运行逻辑

创建日期：2026-05-17

目标

设计一个后续可实现为 Codex Skill 的广告优化流程，用于基于产品事实、Sorftime 自然排名数据、领星历史广告投放数据，生成可执行的 Amazon PPC 广告架构和优化建议。

当前阶段只整理运行逻辑，不创建 Skill，不调用领星写入接口，不直接修改广告。

核心原则

这个 Skill 的目标不是单纯“生成广告结构”，而是完成一条证据链：

产品理解
  -> 关键词语义与意图分类
  -> STAG 广告架构
  -> 历史投放表现对照
  -> 广告优化建议

每一步都必须能说明：

使用了什么数据
如何处理
输出了什么中间结果
这些结果支撑什么广告判断

数据来源

Sorftime MCP

用于获取市场与自然流量证据。

可用数据：

数据 用途
产品详情 获取标题、价格、类目、评分、评论数、月销量、主图等
产品标题和五点描述 理解产品卖点、功能、属性和使用场景
产品自然排名关键词 判断产品已经被哪些关键词自然识别
关键词搜索量、排名、CPC 趋势 判断关键词机会和竞争强度
竞品流量词 补充关键词池和对标对象

领星 API

用于获取历史广告表现。

可用数据：

数据 用途
广告账号 / profile_id 定位广告账户
Portfolio 广告组合 找到指定广告组合下的广告活动
SP Campaign / Ad Group / Keyword / Target 还原 SP 投放结构
SB Campaign / Ad Group / Target / Creative 还原 SB 投放结构
SP / SB 搜索词报告 判断真实搜索词表现
SP / SB 关键词或投放报告 判断关键词和 ASIN 投放效果
SP / SB 已购买商品报告 判断广告实际带动购买的 ASIN
小时数据 做出单时段和预算分配判断

人工输入

用于补足自动数据无法判断的业务边界。

输入 用途
目标 ASIN 或产品链接 定位分析对象
广告组合名称 定位需要分析的 Portfolio
站点 / 店铺 默认 US，但必须确认
目标受众 判断关键词和广告语境是否匹配
业务目标 拉新、控 ACOS、清库存、推新品、抢竞品等
禁投边界 不相关属性、不能承诺的卖点、不能投的竞品或品牌词

强制输入条件

以下数据缺失时，Skill 必须停止，不生成广告优化结论。

必需输入 为什么必须有
目标 ASIN 或产品链接 没有产品对象，无法做产品 DNA 分析
站点 不同站点关键词、广告账号、货币和竞争环境不同
广告组合名称或明确的 Campaign 列表 没有广告范围，无法分析历史投放
最近 3 个月广告报告数据 没有历史表现，无法做优化建议
Sorftime 自然排名关键词数据 没有自然流量基准，无法判断广告与自然承接关系
产品标题、五点描述或产品详情 没有产品事实，关键词分类会变成泛化分类

缺失数据时的停止规则

Skill 必须使用明确状态码结束，而不是硬生成结果。

状态码 触发条件 输出
BLOCKED_NO_PRODUCT 缺少目标 ASIN / 链接 返回缺失项清单
BLOCKED_NO_AD_SCOPE 缺少广告组合名称或 Campaign 范围 要求补广告组合或活动列表
BLOCKED_NO_HISTORY_AD_DATA 没有最近 3 个月广告报告 不生成优化建议，只输出待补数据
BLOCKED_NO_ORGANIC_RANKING 没有自然排名关键词 不生成广告架构，只输出待补数据
BLOCKED_NO_PRODUCT_DNA 缺少标题、五点、详情等产品事实 不做关键词过滤
NEEDS_REVIEW_DATA 缺少评论 VOC，但其他数据齐全 允许继续，但标记 VOC 可信度较低

其中，评论 VOC 是强增强输入。缺少评论时可以继续，但必须在结果中标记：

VOC evidence weak: review data not provided.

增强输入

这些数据不是启动必需项，但会显著提高分析质量。

增强输入 增强效果
Review 文件 提炼用户喜欢点、差评阻断点、误解点
Search Term Report 原始文件 补全领星 API 缺失字段或复核口径
当前广告结构导出 判断是否需要重组 Campaign / Ad Group
当前竞价和预算 输出具体 bid / budget 调整建议
Listing 文案 判断广告词与 Listing 承接是否一致
竞品 ASIN 列表 判断 ASIN 投放和防守/进攻策略

工作流总览

Step 0: 输入门禁
Step 1: 产品 DNA 与 COSMO 结构化理解
Step 2: 关键词清洗与多维分类
Step 3: 生成 STAG 广告架构
Step 4: 拉齐历史广告表现
Step 5: 广告架构 vs 历史数据交叉诊断
Step 6: 输出优化建议与执行清单

Step 0：输入门禁

目标

确认是否具备运行条件。

检查项

检查项 通过条件
产品对象 有 ASIN 或产品链接
市场范围 有站点，默认 US 也要显式写入
广告范围 有 Portfolio 名称或 Campaign 列表
时间范围 默认最近 3 个月，允许用户指定
自然排名数据 Sorftime 能返回产品关键词自然排名
历史广告数据 领星能返回 SP / SB 报表
产品信息 有标题、五点描述或产品详情

输出

输出 内容
input_gate_result PASS / BLOCKED / NEEDS_CONTEXT
missing_inputs 缺失数据清单
data_plan 后续需要拉取哪些数据

Step 1：产品 DNA 与 COSMO 结构化理解

目标

深入理解产品，避免广告结构只按词面机械分类。

输入

输入 来源
产品标题、五点描述、类目、价格、评分、评论数 Sorftime
自然排名关键词 Sorftime
Review 正评 / 差评 Sorftime 或上传文件
目标受众和业务目标 用户输入

分析框架

借鉴 COSMO 结构化字段，输出 15 个维度：

维度 说明
is_a 产品是什么类型
used_as 可以替代什么或等效什么
used_on 作用对象或使用对象
used_in_location 使用地点
used_for_func 具体功能
capable_of 扩展能力
used_for_event 使用场景、节日、特殊情境
used_to 用户想达成的目标
used_with 搭配使用产品
used_by 谁使用
xInterest_in 用户兴趣偏好
xIs_a 用户身份
xWant 用户愿望和动机
used_for_audience 目标受众
used_in_body 身体部位或动作关联

额外诊断

诊断项 来源
Top 3-5 Selling Points 标题、五点、评论、自然词
Top 3 Deal Breakers 差评、低相关搜索词、产品不具备属性
Negative Attribute List 产品没有的材质、尺寸、人群、场景、功能
Product DNA Summary 可用于后续关键词过滤和分组

输出

输出物 用途
product_dna_table.md 产品结构化理解
selling_points.json 后续广告卖点映射
deal_breakers.json 后续关键词剔除和否定词
negative_attributes.csv 否词和过滤规则

Step 2：关键词清洗与分类

目标

把自然排名词、历史广告词、搜索词、ASIN Target 统一清洗成可投放的关键词资产。

输入

输入 来源
产品自然排名关键词 Sorftime
历史广告关键词 领星 SP / SB 报告
历史搜索词 领星 SP / SB Search Term 报告
历史 ASIN Target 领星 Target 报告
Deal Breakers / Negative Attributes Step 1

清洗规则

规则 说明
去重 统一大小写、单复数、标点、空格
剔除不相关属性 如产品不是 glass，就剔除 glass 相关词
剔除误导词 包含产品无法满足的功能或人群
保留高意图长尾词 即使搜索量小，也进入 Conversion 层
标记自然排名状态 区分已有自然排名、无自然排名、自然排名弱
标记历史投放状态 区分已投放、未投放、花费高未转化

分类框架

同时输出两套分类，后续合并使用。

1. Funnel 分类

层级 定义 典型词
Awareness 泛词、大词、场景词 water bottle, travel cup
Consideration 品类词、功能词、竞品对比词 insulated water bottle, bottle with straw
Conversion 长尾词、精准词、品牌词、高意图词 32 oz insulated bottle leakproof

2. Root Attribute 分类

按产品属性词根聚类：

类型 示例
材质 stainless steel, metal
容量 20oz, 32oz, 40oz
功能 insulated, leakproof, misting
使用场景 gym, hiking, soccer
人群 kids, women, athletes
搭配对象 phone holder, straw, lid
竞品 / ASIN competitor ASIN, brand terms

输出

输出物 用途
keyword_cleaned_master.csv 清洗后的关键词主表
keyword_funnel_table.md 漏斗层级分类
keyword_root_attribute_table.md 属性词根聚类
excluded_keywords.csv 剔除词和原因
negative_keyword_candidates.csv 否定关键词候选

Step 3：生成 STAG 广告架构

目标

基于产品 DNA 和关键词分类，生成精细化广告结构。

约束

约束 规则
Campaign / Ad Group 1 Campaign = 1 Ad Group
单组关键词数量 每组最多 25 个关键词
高相关性 泛词不能和具体属性长尾词混在同一组
拆分规则 超过 25 个词拆成 Part 1 / Part 2
命名规范 SP - [属性词] - [Part X] - [Match Type]

广告类型策略

层级 推荐广告类型 策略
Awareness SP Broad / SB Video / SB Category 低竞价探索，控预算
Consideration SP Phrase / SP Exact / SB Keyword 中竞价，筛选有效词
Conversion SP Exact / SP Product Targeting / SB Brand Defense 高相关词高优先级
ASIN Target SP Product Targeting / SD Product Targeting 按竞品强弱分组

输出表字段

字段 说明
Campaign Type SP / SB / SD
Campaign Name 标准命名
Ad Group Name 通常与 Campaign 对应
Funnel Level Awareness / Consideration / Conversion
Root Attribute 该组词根
Keywords or ASINs 样例词或 ASIN
Keyword Count 数量
Match Type Broad / Phrase / Exact / Product Targeting
Bid Strategy High / Mid / Low
Reason 为什么这样分组

输出

输出物 用途
ad_architecture_stag.md 广告结构主表
campaign_build_plan.csv 可转广告导入模板的数据基础
negative_phrase_list.csv 否定词建议
campaign_naming_map.csv 命名映射

Step 4：历史广告数据拉齐

目标

把过去 3 个月真实投放表现整理到同一口径。

输入

输入 来源
Portfolio 名称 用户输入
Campaign 列表 领星广告活动接口
SP / SB 关键词报表 领星
SP / SB 搜索词报表 领星
SP / SB ASIN / Target 报表 领星
已购买 ASIN 报表 领星

拉取逻辑

  1. 通过广告账号接口获取 profile_id。
  2. 通过 Portfolio 名称匹配 portfolio_id。
  3. 查询 Portfolio 下的 SP / SB Campaign。
  4. 逐日循环最近 3 个月 report_date。
  5. 分别拉取关键词、搜索词、Target、购买 ASIN 报表。
  6. 按 Campaign / Ad Group / Keyword / Search Term / Target 聚合。

统一指标

指标 说明
impressions 曝光
clicks 点击
cost 花费
sales 广告销售额
orders 订单
units 销量
ctr 点击率
cpc 平均点击成本
cvr 转化率
acos 广告成本销售比
roas 广告投入产出比

输出

输出物 用途
ad_history_raw/ 原始日维度 JSON / CSV
ad_history_normalized.csv 标准化后的广告表现主表
ad_history_by_keyword.csv 关键词聚合
ad_history_by_search_term.csv 搜索词聚合
ad_history_by_asin_target.csv ASIN Target 聚合
ad_history_by_campaign.csv Campaign 聚合

Step 5：广告架构与历史表现交叉诊断

目标

把 Step 3 的理想广告结构和 Step 4 的真实历史表现对照，判断哪些该保留、重组、加预算、降竞价、暂停或否定。

判断维度

诊断项 判断逻辑
高自然排名 + 高广告花费 可能可以降竞价或控制预算
无自然排名 + 高转化 适合继续广告拉排名
高点击无转化 检查是否不相关、Listing 承接弱、价格问题
高转化低曝光 适合加预算、提高竞价、拆 Exact
搜索词转化好但未独立投放 提取为 Exact Campaign
ASIN Target 转化好 拆为单独 ASIN Target 组
ASIN Target 花费高无单 降竞价或否定
SB 表现弱但 SP 表现强 优先 SP 收敛，SB 用于品牌或视频辅助
广泛词花费高 转为低预算探索或暂停

输出标签

标签 含义
Scale 加预算 / 提竞价
Harvest 从搜索词提取为精准投放
Defend 品牌词或核心词防守
Reduce Bid 降竞价
Pause 暂停
Negative 加否定
Restructure 重组 Campaign / Ad Group
Watch 数据不足，继续观察

Step 6：广告优化建议输出

目标

输出给运营可执行的优化清单，而不是只给分析结论。

输出结构

输出模块 内容
总结 Portfolio 过去 3 个月表现概览
产品 DNA 产品定位、核心卖点、Deal Breakers
关键词资产 Funnel 分类 + Root Attribute 分类
新广告架构 STAG Campaign / Ad Group 表
历史表现诊断 关键词、搜索词、ASIN Target 诊断
优化动作清单 具体到 Campaign / Keyword / ASIN 的动作
否定词建议 Phrase / Exact 否定
风险与待确认 数据不足、口径不明、需要人工确认项

优化动作表字段

字段 说明
Action Scale / Pause / Negative / Harvest / Restructure
Object Type Campaign / Keyword / Search Term / ASIN Target
Object Name 操作对象
Current Evidence 历史数据证据
Organic Evidence 自然排名证据
Recommended Change 具体建议
Expected Impact 预期影响
Risk 风险
Priority High / Mid / Low

运行边界

当前阶段不做

不做事项 原因
不直接改广告后台 避免误操作
不调用写入接口 当前只做分析和建议
不自动上传广告 CSV 需要人工确认
不在缺数据时硬生成完整结论 避免伪分析
不混用不同站点数据 站点关键词和广告表现不可直接合并

后续 Skill 可以做

功能 条件
自动拉 Sorftime 数据 需要 ASIN / 站点
自动拉领星广告数据 需要 Portfolio / sid / profile_id / 时间范围
自动生成广告架构 需要产品 DNA + 关键词主表
自动输出优化建议 需要历史广告数据
自动生成广告导入 CSV 需要人工确认结构

SKILL.md 应保持简短，只写触发条件、强制门禁、核心流程和输出要求。详细提示词、字段解释、报表口径放到 references/。

待确认问题

正式创建 Skill 前，需要确认以下规则：

问题 需要确认
评论 VOC 是否强制 当前建议为增强输入，不强制
默认时间范围 当前建议最近 3 个月
只分析 Portfolio，还是也支持单 Campaign 当前建议两者都支持，但优先 Portfolio
是否输出广告导入 CSV 当前建议先只输出结构，不直接导入
是否包含 SD 当前用户重点是 SP / SB，SD 可作为二期
预算建议是否给具体金额 需要拿到当前预算和业务目标后再给
Bid 建议是否给具体数值 需要历史 CPC / CVR / ACOS 后再给
